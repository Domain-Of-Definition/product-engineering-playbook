# Product Engineering Playbook

[English Version](./README_EN.md)

这是一个用于持续沉淀产品设计、功能设计、系统设计与软件开发经验的个人知识库。

这个仓库记录我在实际产品开发过程中积累的设计思路、技术方案、决策过程、工程实践以及踩坑经验，覆盖从需求理解、产品方案设计，到系统架构和最终软件实现的完整过程。

相比单纯记录某项技术“怎么使用”，这个仓库更关注：

- 为什么会遇到这个问题
- 我是如何分析问题的
- 有哪些可选方案
- 最终为什么选择当前方案
- 不同方案之间有哪些取舍
- 实际实施后的结果如何
- 哪些经验可以抽象成以后继续复用的方法

目标是逐步将零散的项目经验整理为一套属于自己的 **产品与工程方法论（Product Engineering Playbook）**。

---

## 内容目录

### [产品设计 Product Design](./product-design/)

关注一个产品 **应该解决什么问题、为什么要做，以及应该做什么**。

主要包括：

- 需求分析
- 用户与使用场景分析
- 产品目标拆解
- 产品流程设计
- MVP 范围定义
- 功能优先级
- 产品闭环设计
- 产品方案决策
- 产品方案取舍

核心问题：

> 我们到底应该构建什么产品，以及为什么？

---

### [功能设计 Feature Design](./feature-design/)

关注产品方向确定之后，某个具体功能 **应该如何工作**。

主要包括：

- 用户操作流程
- 功能状态设计
- 业务规则
- 正常流程
- 异常流程
- 边界情况
- 权限设计
- Loading / Empty / Error 状态
- 前后端交互
- 功能级方案取舍

核心问题：

> 这个功能具体应该如何运行？

---



### [系统设计 System Design](./system-design/)

关注如何通过合理的技术架构 **支撑产品与功能需求**。

主要包括：

- 系统架构
- 服务与模块划分
- API 设计
- 数据库设计
- 数据模型
- 数据流
- 身份认证与权限架构
- 缓存
- 消息队列
- 文件存储
- 第三方服务集成
- AI / LLM 系统架构
- 可扩展性
- 性能
- 可靠性
- 安全性
- 架构方案取舍

核心问题：

> 技术系统应该如何设计，才能合理地支撑产品？

---



### [软件开发 Software Development](./software-development/)

关注如何真正将设计方案 **实现、测试、调试、部署和维护**。

主要包括：

- 后端开发
- 前端开发
- 数据库开发
- 编码实践
- 框架使用经验
- Debug 方法
- Git 工作流
- 自动化测试
- CI/CD
- Docker 与部署
- 日志与异常处理
- 数据库 Migration
- 性能优化
- AI / LLM API 接入
- 工程效率优化

核心问题：

> 如何高质量地把方案真正实现出来？

## 我的经验记录方式

这个仓库中的经验文章通常会按照下面的结构进行整理：

### 1. 背景 Context

当时处于什么项目、业务或开发场景？

### 2. 问题 Problem

具体遇到了什么问题？

### 3. 约束 Constraints

方案设计过程中存在哪些业务、产品、技术、时间或资源限制？

### 4. 分析 Analysis

我是如何理解和分析这个问题的？

### 5. 方案 Solution

最终采用了什么产品设计、技术方案或实现方式？

### 6. 备选方案 Alternatives Considered

还考虑过哪些其他方案？

### 7. 方案取舍 Trade-offs

为什么最终选择当前方案？

这个方案带来了什么收益，又引入了哪些成本或复杂度？

### 8. 结果 Result

方案落地后的实际效果如何？

### 9. 经验总结 Lessons Learned

通过这次实践，我学到了什么？

### 10. 可复用原则 Reusable Principles

哪些经验可以进一步抽象成未来面对类似问题时可以直接复用的方法或原则？

## 从项目经验到方法论

这个仓库希望完成这样一个持续积累的过程：

```text
实际项目
   ↓
具体问题
   ↓
分析与方案
   ↓
设计决策
   ↓
实施结果
   ↓
经验总结
   ↓
可复用原则
   ↓
个人方法论
```

随着项目经验增加，这些内容也会持续整理和迭代。

最终目标不是简单建立一个“开发笔记仓库”，而是形成一套能够体现完整产品与工程思考过程的个人 **Product Engineering Playbook**。
