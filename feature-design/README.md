# Feature Design｜功能设计

本目录用于记录具体产品功能的详细设计经验。

当产品已经确定“需要提供某项能力”之后，这里进一步研究：

> **这个功能具体应该怎样工作？**

重点关注用户行为、业务规则、字段、状态、流程、异常情况以及功能之间的联动关系。

------

## 关注的问题

主要包括：

- 功能流程设计
- 用户操作路径
- 字段设计
- 表单设计
- 查询与筛选
- 功能状态设计
- 状态流转
- 业务规则
- 权限对功能行为的影响
- 正常流程
- 异常流程
- 边界场景
- Loading / Empty / Error 状态
- 批量操作
- 导入 / 导出体验
- 页面交互规则
- 功能之间的联动关系

------

## 与其他目录的边界

### Feature Design vs Product Design

Product Design 决定：

> **要不要做、做什么。**

Feature Design 决定：

> **确定要做以后，它具体怎么工作。**

例如：

```text
产品设计：
需要提供批量导入能力，提高基础数据录入效率。

功能设计：
用户上传什么格式的文件？
哪些字段必填？
重复数据怎么处理？
失败以后怎么反馈？
```

### Feature Design vs System Design

Feature Design 使用业务和用户能够理解的语言描述功能行为。

例如：

```text
一个人员可以关联多套房屋。
```

至于技术上应该使用：

```text
主表 + 关系表
```

还是其他数据结构，则属于 System Design。

### Feature Design vs Software Development

Feature Design 定义：

> 功能应该表现成什么样。

Software Development 负责：

> 如何通过代码可靠地实现这些规则。
