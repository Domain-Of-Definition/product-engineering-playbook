# System Design｜系统设计

本目录用于记录为了支撑产品和业务需求而进行的**技术系统设计与架构决策**。

这里关注的不只是某段代码如何实现，而是：

> **系统应该采用什么结构，才能合理、可靠、可扩展地支撑业务？**

------

## 关注的问题

主要包括：

- 系统架构
- 模块与服务划分
- 数据模型设计
- 数据库设计
- 关系数据建模
- API 设计
- 数据流设计
- 身份认证
- 功能权限
- 数据权限
- 多租户 / 多项目数据隔离
- 状态模型
- 软删除
- 数据生命周期
- 审计与变更记录
- 缓存设计
- 消息队列
- 文件存储
- 第三方系统集成
- AI / LLM 系统架构
- 性能
- 可扩展性
- 可靠性
- 安全性
- 技术方案 Trade-off

## 与其他目录的边界

### System Design vs Feature Design

Feature Design 描述业务规则：

```text
一个人员可以关联多个房屋。
```

System Design 则需要进一步回答：

```text
应该如何存储这种关系？

是否建立独立关系表？

关系是否具有状态？

是否需要记录生效时间和失效时间？
```

因此：

> Feature Design 关注“业务上是什么”，System Design 关注“系统上如何表达”。

### System Design vs Software Development

System Design 更关注方案和结构。

Software Development 更关注：

- 如何编码实现
- 如何处理事务
- 如何测试
- 如何 Debug
- 如何部署
- 如何验证实际运行结果

例如：

```text
System Design：
关键写操作需要保证原子性。

Software Development：
具体如何划分事务边界以及处理回滚。
```
